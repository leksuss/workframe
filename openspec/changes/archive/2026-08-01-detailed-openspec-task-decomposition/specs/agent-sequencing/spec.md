## ADDED Requirements

### Requirement: Исполнимая декомпозиция задач OpenSpec

Workframe MUST требовать, чтобы `tasks.md` декомпозировал работу до уровня, на котором исполнитель может выполнить пункт без неявного продуктового или архитектурного решения. Каждый неатомарный пункт MUST описывать ожидаемый результат, затрагиваемую область, существенные ограничения и способ проверки; эти сведения могут быть кратко записаны в пункте или даны точной ссылкой на соответствующий OpenSpec artifact.

#### Scenario: Планировщик создаёт крупный change

- **WHEN** агент создаёт `tasks.md` для change с несколькими зависимыми частями
- **THEN** он сохраняет крупные блоки верхнего уровня и разбивает их на упорядоченные нумерованные подпункты, достаточные для самостоятельной реализации
- **AND** у каждого неатомарного подпункта зафиксированы результат, область, ограничения и проверка

#### Scenario: Решение ещё не принято

- **WHEN** выполнение пункта требует нового продуктового или архитектурного решения
- **THEN** агент сначала фиксирует решение в proposal, design или spec и обновляет задачу
- **AND** не оставляет выбор исполнителю как неявную часть задачи

#### Scenario: Change мал и атомарен

- **WHEN** change состоит из одного самостоятельного небольшого изменения
- **THEN** `tasks.md` может использовать плоский список без искусственного дробления

### Requirement: Проверяемая передача работы между агентами

Workframe MUST требовать от исполнителя остановиться и обновить или запросить уточнение OpenSpec artifacts, если план не содержит решения, необходимого для безопасного выполнения. Перед завершением change ревьюер MUST сопоставить выполненные пункты с их ожидаемым результатом и способом проверки.

#### Scenario: Исполнитель находит неясный пункт

- **WHEN** исполнитель не может безопасно выполнить пункт без нового решения
- **THEN** он не угадывает решение в реализации
- **AND** останавливает работу для уточнения или обновления OpenSpec artifacts

#### Scenario: Ревью завершённого change

- **WHEN** все пункты `tasks.md` отмечены выполненными
- **THEN** ревьюер проверяет соответствие реализации ожидаемому результату и проверке каждого пункта
- **AND** не ограничивается наличием отметок в списке задач
