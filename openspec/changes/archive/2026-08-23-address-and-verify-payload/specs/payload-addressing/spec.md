## ADDED Requirements

### Requirement: Адресуемость файлов payload

Workframe MUST NOT поставлять в генерируемый проект файл, на который не ссылается ни одно правило, приезжающее в тот же проект. Адрес MUST называть момент применения файла и его путь, и MUST находиться там, где агент проекта его прочитает: в `template/base/AGENTS.md` либо в файле payload, который правила уже адресуют. Документация, остающаяся в репозитории Workframe, адресом не является.

#### Scenario: Чек-лист приезжает в проект

- **WHEN** payload содержит чек-лист в `docs/checklists/`
- **THEN** правила проекта называют момент, в который он применяется, и его путь
- **AND** отсутствие входящей ссылки считается дефектом payload, а не свойством справочного файла

#### Scenario: Файл приходит только с optional module

- **WHEN** файл устанавливается лишь при выборе модуля
- **THEN** адрес формулируется условно — «если файл установлен»
- **AND** остаётся корректным в проекте, где модуль не выбран

#### Scenario: Change добавляет новый файл payload

- **WHEN** Workframe change добавляет файл в `template/base/` или в payload модуля
- **THEN** адрес этого файла появляется в том же change
- **AND** change не считается завершённым, пока файл не адресован

#### Scenario: Файл описывает сам себя вовне проекта

- **WHEN** единственное упоминание файла payload находится в `docs/UPGRADING.md`, README Workframe или README модуля
- **THEN** файл считается неадресованным
- **AND** адрес добавляется в правила, приезжающие в проект

### Requirement: Указатель ссылается, а не пересказывает

Адрес MUST ограничиваться путём и моментом применения. Содержание адресуемого файла MUST NOT переноситься в правила, потому что две копии одного содержания расходятся при первой правке одной из них.

#### Scenario: Содержание адресуемого файла меняется

- **WHEN** проект добавляет, убирает или переформулирует пункт чек-листа
- **THEN** изменение вносится только в чек-лист
- **AND** указатель в правилах остаётся верным без правки

#### Scenario: Адрес ставится в правилах

- **WHEN** правило получает ссылку на чек-лист
- **THEN** ссылка не воспроизводит его пункты, условия применения по каждому пункту и обоснование
- **AND** правило остаётся источником обоснования, а чек-лист — источником шагов

### Requirement: Чек-лист называет шаги правила, которое обслуживает

Чек-лист payload MUST называть каждый шаг, которого действующее правило требует в области этого чек-листа. Шаг формулируется как действие; обоснование, классификация находок и иерархия артефактов остаются в правилах.

#### Scenario: Правило требует шага, отсутствующего в чек-листе

- **WHEN** правила требуют действия в области чек-листа, а чек-лист его не называет
- **THEN** шаг вносится в чек-лист
- **AND** вносится формулировка действия, а не обоснование правила

#### Scenario: Чек-лист расходится с правилом

- **WHEN** сверка обнаруживает, что чек-лист и обслуживаемое им правило требуют разного
- **THEN** расхождение классифицируется по действующим правилам согласованности
- **AND** чек-лист не считается независимым источником требований
