## MODIFIED Requirements

### Requirement: Read-only проверка обновления проекта
Workframe MUST предоставлять `scripts/check-workframe-update.sh --target <path>` для проверки существующего проекта без изменения файлов target project. Отчёт MUST показывать применённую версию marker, текущий root `VERSION`, modules из marker (или `unknown`), релизные заметки и следующий шаг с project-local OpenSpec change. Отчёт MUST сравнивать установленный payload с шаблоном пофайлово — весь `template/base` и payload установленных modules — и печатать для каждого файла `equal`, `differs` или `missing`. Файлы, которые проект обязан вести сам, MUST выводиться отдельной секцией, где расхождение является ожидаемым состоянием.

#### Scenario: Проект отстаёт от Workframe
- **WHEN** владелец запускает проверку для проекта, чей marker содержит более раннюю версию
- **THEN** скрипт не изменяет target project и выводит версии, релизные заметки, пофайловое состояние payload и инструкцию создать `upgrade-workframe-guidance`

#### Scenario: Старый marker не содержит modules
- **WHEN** `.project-workframe-version` проекта не содержит поля `modules`
- **THEN** скрипт выводит `modules: unknown`, определяет установленные modules по наличию их payload в проекте и сообщает, что состав определён по файлам

#### Scenario: Канонический файл изложен своими словами
- **WHEN** установленная копия канонического файла payload не совпадает с шаблоном побайтово
- **THEN** отчёт печатает для этого файла `differs`
- **AND** не предлагает перезапись и не завершается ошибкой

#### Scenario: Project-local файл расходится с шаблоном
- **WHEN** сравниваются `docs/CONCEPTS.md`, `docs/QUALITY.md`, `docs/DEBT.md` или `.project-workframe-version`
- **THEN** они выводятся отдельно от канонических файлов
- **AND** их расхождение не считается поводом к правке

### Requirement: Marker установленных modules
Штатный init Workframe MUST записывать в `.project-workframe-version` все modules, которые он установил: `agent-skills` и выбранные optional modules. Marker MUST NOT считаться доказательством фактического состояния проекта: он записывает применённое намерение, а проверка обновления сверяет содержимое.

#### Scenario: Инициализация с optional modules
- **WHEN** владелец запускает init с `design-pencil` и `frontend-quality`
- **THEN** marker содержит `modules: agent-skills,design-pencil,frontend-quality`

#### Scenario: Marker расходится с содержимым
- **WHEN** версия в marker не соответствует уровню установленных файлов
- **THEN** отчёт печатает обе величины: записанную в marker и вычисленную по содержимому

## ADDED Requirements

### Requirement: Фактический уровень содержимого проекта

Проверка обновления MUST вычислять уровень содержимого проекта сравнением его канонических файлов с шаблонами выпущенных версий Workframe, доступных в checkout, а не принимать значение marker. Уровнем MUST считаться самая новая версия, шаблон которой совпадает со всеми каноническими файлами проекта. Отчёт MUST называть релизы, доступные для сравнения.

#### Scenario: Содержимое новее записанного в marker

- **WHEN** marker содержит `workframe: 0.1.0`, а канонические файлы совпадают с шаблоном 0.2.0 и не совпадают ни с одним более новым
- **THEN** отчёт печатает уровень содержимого `0.2.0` рядом с версией marker
- **AND** релизные заметки отсчитываются от уровня содержимого, а не от версии marker

#### Scenario: Содержимое собрано из разных версий

- **WHEN** ни один выпущенный шаблон не совпадает со всеми каноническими файлами
- **THEN** уровень печатается как `mixed`
- **AND** для каждого файла указывается самый новый релиз, с которым он совпадает, либо отсутствие такого релиза

#### Scenario: Релиз не имеет тега

- **WHEN** проект собран из версии, выпущенной до введения Git-тегов
- **THEN** отчёт сообщает, что сравнимого шаблона нет, и перечисляет релизы, доступные для сравнения
- **AND** пофайловое состояние относительно текущего шаблона выводится в обычном виде

### Requirement: Побайтовое равенство канонических файлов как условие завершения апгрейда

Payload MUST требовать, чтобы change, обновляющий Workframe payload проекта, завершался побайтовым равенством канонических файлов проекта шаблону целевой версии. Намеренно пропущенная часть MUST быть названа в `notes` маркера. Правила проекта MUST запрещать изложение канонического файла своими словами, а чек-лист аудита MUST повторять эту сверку.

#### Scenario: Upgrade change готов к архивации

- **WHEN** агент завершает change, обновивший Workframe payload проекта
- **THEN** он проверяет побайтовое равенство канонических файлов шаблону целевой версии до предложения archive
- **AND** расхождение либо устраняется копированием, либо объявляется в `notes` маркера как намеренно пропущенное

#### Scenario: Агент воспроизводит канонический файл по памяти

- **WHEN** агент переносит в проект канонический файл payload
- **THEN** правила проекта требуют копирования файла целиком
- **AND** сокращённый пересказ запрещён независимо от того, насколько агент уверен, что понял содержание

#### Scenario: Аудит ищет накопленный дрейф

- **WHEN** в проекте выполняется срез аудита, посвящённый расхождению копий с каноном
- **THEN** он включает сверку установленного payload с шаблоном версии, записанной в marker

#### Scenario: Обычный change не обновляет payload

- **WHEN** change не касается Workframe payload проекта
- **THEN** пункт о побайтовом равенстве к нему не применяется
