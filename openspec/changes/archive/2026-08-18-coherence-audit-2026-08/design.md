## Context

Аудит выполнен по `template/base/docs/checklists/coherence-audit.md` через workflow `coherence-audit`. Область — весь репозиторий, кроме `openspec/changes/archive/`, который является историей и не редактируется.

Реестр `docs/DEBT.md` на момент старта содержал одну запись `D-001` в статусе `resolved`; открытых записей для ре-валидации не было.

## Что дал каждый срез

1. **Ссылочная целостность.** Проверено 69 md-файлов вне архива, 25 кандидатов на неразрешённую ссылку. Ни одной сломанной: все оказались родовыми именами артефактов OpenSpec (`tasks.md`, `proposal.md`, `.openspec.yaml`), сокращёнными упоминаниями (`init-project.sh`) или путями опциональных модулей.
2. **Placeholder.** Два незаполненных `Purpose`, оставленных архивацией. Токены в чек-листе и каноне — цели поиска, не находки. `pending stack selection` в `docs/QUALITY.md` — намеренное состояние.
3. **Объявленное против существующего.** Три расхождения: подмена README генерируемого проекта, неверный заголовок списка в `docs/UPGRADING.md` с пропущенной строкой, отсутствие `source/profiles/` в схеме репозитория.
4. **Спеки против payload.** Требования всех шести capability имеют опору в репозитории. Расхождений нет.
5. **Дубли и расхождения.** Три раздела `AGENTS.md` побайтово совпадают между root и payload. Каталоги `source/profiles/` и `examples/` дублируют одну роль.
6. **Мёртвое.** Мёртвых артефактов нет. `source/profiles/` не мёртв, но не объявлен.
7. **Структура.** Файлы always-on правил выросли до 199 и 216 строк.

## Decisions

### 1. Граница между исправленным и записанным

Исправлено только то, что не требует решения о том, каким Workframe должен быть: заполнение Purpose по фактическому содержанию спек, разделение списка на обязательное и опциональное по фактическому поведению `init-project.sh`, исключение для намеренного состояния quality policy.

Остальное записано. Подмена README требует выбора способа исправления; отношения `source/profiles/` и `examples/` требуют решения, что из этого источник истины; дублирование разделов `AGENTS.md` требует решения о рефакторинге.

### 2. Схема репозитория не дополняется в этом change

`source/profiles/` отсутствует в схеме обоих README. Механически строку добавить можно, но это симптом нерешённого вопроса из `D-003`: если каталог сливается с `examples/` или удаляется, добавленная строка окажется неверной. Правка отложена до решения по `D-003`.

### 3. Заголовок списка в UPGRADING разделён, а не переписан

Список файлов остаётся тем же; меняется только группировка и добавляется пропущенная строка. Это восстанавливает соответствие фактическому поведению `init-project.sh`, не меняя рекомендаций по сравнению файлов при обновлении.

## Risks / Trade-offs

- [Заполненный Purpose разойдётся со спекой при её изменении] → Purpose сформулирован как назначение capability, а не как перечень требований, поэтому не требует правки при добавлении отдельного требования.
- [Записанные находки останутся без движения] → они попадают под правило ре-валидации и принудительного выноса владельцу при следующем аудите.
- [Исключение в чек-листе ослабит срез 2] → исключение названо точечно: намеренная pending-политика payload, требуемая спекой, а не любые вхождения токенов.
