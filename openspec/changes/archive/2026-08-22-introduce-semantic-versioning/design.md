## Context

Workframe уже содержит `.project-workframe-version`, но его начальное значение вручную зашито в template, а текущая версия не имеет единственного источника. `CHANGELOG.md` копит изменения в `Unreleased`, поэтому маркер проекта не позволяет точно определить состояние scaffold.

## Goals / Non-Goals

**Goals:**

- Сделать `VERSION` единственным источником текущей версии Workframe.
- Применять SemVer для каждого завершённого Workframe change и фиксировать номер в `CHANGELOG.md`.
- При инициализации записывать фактическую версию в маркер нового проекта.
- Дать агентам ясный, безопасный процесс обновления существующего проекта.

**Non-Goals:**

- Не обновлять существующие проекты автоматически.
- Не создавать теги или релизы в удалённом Git-репозитории.
- Не навязывать обновление Workframe каждому проектному change.

## Decisions

- `VERSION` в корне — канонический текстовый источник номера. Он прост для ручной проверки, не привязан к языку или package manager и не смешивает версию scaffold с версией какой-либо программы.
- Формат — Semantic Versioning: `MAJOR` для несовместимого изменения обязательного workflow/payload, `MINOR` для обратно совместимой возможности или правила, `PATCH` для обратно совместимого исправления. Каждый завершённый Workframe change выбирает один из этих уровней и повышает `VERSION` до архивации.
- Каждый релиз переносит соответствующие записи из `CHANGELOG.md` `Unreleased` в заголовок версии с датой. Пустой `Unreleased` остаётся заготовкой для следующего change.
- `scripts/init-project.sh` читает root `VERSION` и заменяет в скопированном маркере заполнитель `workframe: VERSION` на это значение; template не дублирует номер. Это сохраняет работоспособность ручного копирования: владелец явно заполняет версию, если не использует скрипт.
- Версия `0.2.0` обозначает обратно совместимое добавление lifecycle для verification и coherence после `0.1.0`; оно уже накоплено в `Unreleased` и включается в этот первый формальный выпуск.

## Risks / Trade-offs

- [Ручная копия template оставит заполнитель] → README и marker требуют заполнить его; штатный скрипт делает это автоматически.
- [Механическое повышение номера без осмысленного выбора] → root `AGENTS.md` требует обосновать SemVer-уровень в OpenSpec change и changelog.
- [Версия не равна Git-тегу] → документация ясно определяет `VERSION` как состояние scaffold; теги остаются отдельной необязательной практикой владельца.
