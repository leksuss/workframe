## Context

`scripts/init-project.sh` копирует base payload и модуль `agent-skills` строками вида `cp -R <dir>/. "$TARGET/"`. Опциональные модули копируются иначе: `design-pencil` — только `.codex`, `frontend-quality` — только `docs/.`. То есть перечисление payload уже является действующим приёмом, и `agent-skills` — единственный модуль, выпадающий из него.

Модуль `agent-skills` содержит четыре каталога payload — `.agents`, `.claude`, `.codex`, `.qwen` — и README, описывающий сам модуль.

`docs/CONCEPTS.md` описывает journey «Adapt Workflow To A Project Type» через чтение профиля. Оба каталога, `source/profiles/` и `examples/`, содержат `django-app`, `telegram-bot` и `scraper-service`, причём файл в `examples/` называет себя «an example profile note».

## Goals / Non-Goals

**Goals:**

- Исключить документацию модуля из генерируемого проекта, не создавая риска удалить чужой файл.
- Привести копирование `agent-skills` к тому же приёму, что у остальных модулей.
- Оставить один каталог с примерами адаптации и однозначные ссылки на него.

**Non-Goals:**

- Не менять состав payload: набор устанавливаемых файлов остаётся прежним за вычетом README модуля.
- Не вводить новых зависимостей ради исключения файла при копировании.
- Не трогать уже созданные проекты.

## Decisions

### 1. Перечисление каталогов payload вместо исключения файла

`init-project.sh` копирует `.agents`, `.claude`, `.codex` и `.qwen` модуля явно.

Альтернатива «скопировать всё и удалить лишнее» отклонена как опасная: `rm` по фиксированному имени в целевом каталоге удалил бы файл проекта, если тот назывался так же. Именно этот класс ущерба и лечится данным change.

Альтернатива с `rsync --exclude` или `tar --exclude` отклонена: она добавляет зависимость от инструмента ради одного файла. Тот же аудит уже устранил необъявленную зависимость от ripgrep, вводить новую сразу после этого неразумно.

Перечисление каталогов не только решает задачу, но и делает три модуля одинаковыми по способу установки.

### 2. Инструкция ручного копирования правится вместе со скриптом

README модуля предлагает `cp -R /path/to/workframe/template/modules/agent-skills/. /path/to/project/` — команду с тем же дефектом. Исправление только скрипта оставило бы документированный путь сломанным.

### 3. `examples/` остаётся, `source/profiles/` удаляется

Выбор владельца. `examples/` уже перечислен в схеме репозитория в обоих README, а `source/profiles/` не упомянут нигде, поэтому правок документации требуется меньше.

Затрагивается `docs/CONCEPTS.md`: принцип на строке 34 и journey на строке 54 говорят о профилях как об отдельной сущности. Обычно конституция не правится без явной просьбы; здесь правка санкционирована решением владельца по `D-003` и ограничена заменой исчезнувшей сущности, без изменения смысла принципа и journey.

`CHANGELOG.md` не правится: запись о профилях относится к выпущенной версии 0.1.0 и описывает, что было сделано тогда. Переписывать историю выпусков нельзя.

## Risks / Trade-offs

- [Забыт каталог payload при перечислении] → проверка `verify-agent-adapters.sh` инициализирует временный проект и требует наличия всех пяти скиллов во всех трёх клиентских каталогах плюс каноническом; пропуск каталога уронит её.
- [Проект по-прежнему получит README при ручном копировании старой командой] → команда исправлена в том же файле, где её читают.
- [Ссылка на профили осталась незамеченной] → перед удалением собраны все упоминания вне удаляемого каталога; их шесть, судьба каждого определена в этом design.
