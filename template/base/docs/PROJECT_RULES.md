# Project Rules

Rules this project decided for itself live here: conventions, granularity preferences, extra release gates, domain constraints, adaptations of a Workframe rule to local circumstances.

`AGENTS.md`, `docs/AGENT_WORKFLOW.md`, and the checklists come from Workframe and stay byte-identical to the template, so an upgrade can prove that nothing was quietly restated. A rule that would otherwise be an edit to one of those files belongs in this file instead.

Say what the rule requires and when it applies. Keep the reasoning to a sentence. When a rule adapts a canonical one, name the canonical rule it adapts.

This file ships empty, and an empty file is the normal state for a project that follows Workframe as it is.
